# 实时检测子系统使用说明

## 1. 系统概述

实时检测子系统是“两客一危”重大交通安全事故智能决策与救援系统中的交通事故智能检测模块，主要用于对交通事故现场图像、视频和实时视频流进行目标识别与事故状态判断。系统基于 YOLO 系列目标检测模型构建，提供图片检测、视频检测、实时检测、历史记录查询和统计分析等功能。

本子系统面向两类典型事故场景：客车追尾现场和油罐车泄露现场。系统可根据用户选择的检测任务和模型，对输入数据中的车辆、火灾、泄露事故等目标进行识别，并输出检测框、类别标签、置信度和检测结果图像。

子系统由 Flask 后端服务和 Vue 前端界面组成。后端负责模型加载、检测推理、结果保存、历史记录管理和系统状态接口；前端负责用户操作、检测结果展示、模型参数设置和运行状态可视化。

主要功能包括：

- 图片检测：上传单张图片并返回检测结果。
- 视频检测：上传本地视频并进行抽帧检测。
- 实时检测：支持本地摄像头或实时视频流检测。
- 模型配置：支持检测模式、检测任务、模型、置信度和 IOU 阈值设置。
- 历史记录：保存并查询检测记录。
- 统计分析：展示检测次数、类别分布、模型使用情况和推理耗时等统计信息。
- 系统集成：支持与总系统前端和 Integration Hub 进行联动。

## 2. 运行环境与启动方式

### 2.1 运行环境要求

建议在项目约定的 Conda 环境中运行本子系统：

```bash
conda activate lkywSystem
```

基础环境要求如下：

- Python 3.8 或以上版本。
- Node.js 和 npm，用于运行 Vue 前端。
- CUDA 环境可选，用于 GPU 加速推理。
- 建议内存 8GB 或以上。
- 如需实时视频检测，建议使用具备稳定显存的 NVIDIA GPU。

### 2.2 后端启动方式

进入实时检测子系统目录：

```bash
cd Real-time_Detection
```

启动后端服务：

```bash
bash start_backend.sh
```

也可以手动启动后端：

```bash
cd web_app/backend
python app.py
```

后端默认监听地址为：

```text
http://127.0.0.1:5000
```

后端健康检查地址为：

```text
http://127.0.0.1:5000/api/health
```

访问该地址后，如果返回服务状态、模型状态和实时流状态等信息，说明后端服务已正常运行。

### 2.3 前端启动方式

在实时检测子系统目录下启动前端：

```bash
bash start_vue.sh
```

也可以手动启动前端：

```bash
cd web_app/frontend/vue-frontend
npm install
npm run dev
```

前端默认访问地址为：

```text
http://127.0.0.1:3000
```

启动成功后，在浏览器中打开该地址即可进入实时检测子系统界面。

### 2.4 服务状态检查

进入前端页面后，页面顶部会显示服务状态。当后端正常运行且前端能够访问后端接口时，状态显示为“服务在线”；如果后端未启动、端口错误或网络访问失败，状态显示为“服务离线”。

若服务离线，应优先检查：

- 后端服务是否已启动。
- 后端端口是否为 5000。
- 浏览器是否能够访问 `/api/health`。
- 模型权重文件是否存在。
- 防火墙或代理是否影响本地访问。

## 3. 系统界面说明

系统主界面由顶部导航栏、左侧模型配置区、中间检测功能区和右侧算法推理监控面板组成。

### 3.1 顶部导航栏

顶部导航栏用于切换系统功能页面，包含以下入口：

- 图片检测。
- 视频检测。
- 实时检测。
- 历史记录。
- 统计仪表板。

导航栏右侧显示服务在线状态和模型状态，用于判断当前系统是否能够正常执行检测任务。

### 3.2 模型配置区

模型配置区用于设置检测前的关键参数，包括检测模式、检测任务线、模型、置信度阈值和 IOU 阈值。

检测模式包括：

- 单任务检测：只针对一个任务线执行检测。
- 综合事故检测：同时使用客车追尾现场模型和油罐车泄露现场模型进行联合推理。

在单任务检测模式下，用户需要选择检测任务线：

- 客车追尾现场。
- 油罐车泄露现场。

置信度阈值用于控制检测结果的可信程度。阈值越高，保留下来的目标越可靠，但可能漏检部分目标；阈值越低，系统更容易检出目标，但误检可能增加。

IOU 阈值用于控制重叠检测框的合并与筛选。实际使用中可保持默认值，仅在检测框重叠较多或目标重复显示时进行调整。

### 3.3 检测结果展示区

检测结果展示区位于页面中部，根据当前导航页签显示不同内容：

- 图片检测页面显示上传图片、检测结果图和检测明细。
- 视频检测页面显示视频上传、抽帧检测结果和检测摘要。
- 实时检测页面显示实时视频流画面和当前检测状态。
- 历史记录页面显示已保存的检测记录。
- 统计仪表板页面显示检测统计数据。

### 3.4 算法推理监控面板

算法推理监控面板展示当前系统运行状态，包括：

- GPU 名称。
- CUDA 版本。
- 当前推理模型。
- 平均推理时间。
- 今日检测次数。
- 累计检测次数。
- 已加载模型数。
- 显存占用曲线。
- GPU 负载曲线。
- 温度变化曲线。

该面板主要用于判断模型推理是否正常、硬件资源是否充足，以及实时检测是否存在明显性能瓶颈。

## 4. 模型与检测类别说明

### 4.1 支持模型

系统当前支持客车追尾现场和油罐车泄露现场两类任务模型。

客车追尾现场检测模型包括：

- SFGA-YOLO26M。
- YOLO26M。
- YOLO11M。

油罐车泄露现场检测模型包括：

- LCA-YOLO26N。
- YOLO26N。
- YOLO11N。

其中，SFGA-YOLO26M 和 LCA-YOLO26N 为对应任务线的主要改进模型，其他模型可作为对照模型或备选模型使用。

### 4.2 检测模式

系统支持单任务检测和综合事故检测两种模式。

单任务检测适用于已知事故场景的检测任务。例如，当输入数据主要来自客车追尾事故现场时，可选择“客车追尾现场”任务线，并选择对应模型进行检测。

综合事故检测适用于事故类型不确定或需要同时覆盖多类事故风险的场景。该模式下，系统会结合客车追尾现场模型和油罐车泄露现场模型进行联合推理，从而同时识别不同任务线下的事故目标。

### 4.3 检测类别

客车追尾现场相关类别主要包括：

- 普通车辆火灾。
- 普通车辆正常。
- 两客一危车辆火灾。
- 两客一危车辆正常。

油罐车泄露现场相关类别主要包括：

- 油罐车正常。
- 油罐车泄露事故。

检测结果中通常会显示目标类别、置信度和目标框位置。若检测结果中出现火灾、泄露事故等异常类别，应结合原始图像或视频画面进行复核，并按业务流程进行后续处置。

### 4.4 模型权重放置要求

系统会优先从以下目录扫描模型权重：

```text
LKYWDataset_weights/*/best.pt
```

如果该目录下没有可用模型，系统会尝试使用默认回退路径：

```text
runs/detect/lkyw_fire_detection/weights/best.pt
```

模型文件通常命名为 `best.pt`。若模型未正确放置，前端可能显示模型未就绪，后端健康检查接口也会返回模型不可用状态。

## 5. 检测功能使用说明

### 5.1 图片检测

图片检测用于对单张事故现场图片进行目标识别。

操作步骤如下：

1. 打开前端页面，进入“图片检测”页签。
2. 在左侧模型配置区选择检测模式。
3. 如使用单任务检测，选择对应任务线和模型。
4. 根据需要调整置信度阈值和 IOU 阈值。
5. 上传待检测图片。
6. 等待系统完成推理。
7. 查看检测结果图和检测明细。

系统支持的图片格式包括：

- png。
- jpg。
- jpeg。
- bmp。
- webp。

检测完成后，系统会在结果图中绘制目标框，并标注类别和置信度。检测记录会保存到历史记录中，便于后续查询。

### 5.2 视频检测

视频检测用于对本地视频文件进行抽帧检测，适合分析事故过程视频或监控录像片段。

操作步骤如下：

1. 进入“视频检测”页签。
2. 设置检测模式、任务线、模型和阈值参数。
3. 上传待检测视频文件。
4. 系统对视频进行抽帧并执行检测。
5. 查看关键帧检测结果和检测摘要。

系统支持的视频格式包括：

- mp4。
- avi。
- mov。

默认最大上传文件大小为 100MB。若视频文件较大，建议先进行裁剪、压缩或截取关键片段后再上传检测。

### 5.3 实时检测

实时检测用于接入本地摄像头或实时视频流，并持续输出检测结果。

操作步骤如下：

1. 进入“实时检测”页签。
2. 设置检测模式、任务线、模型和阈值参数。
3. 配置摄像头或视频流地址。
4. 启动实时检测。
5. 在页面中查看实时画面和检测结果。
6. 检测结束后停止实时检测。

实时视频流可用于接入摄像头、RTSP 流或 RTMP 推流。使用 OBS 推流时，可根据系统配置将视频推送到本地流媒体地址，再由实时检测模块读取并检测。

实时检测对硬件资源要求较高。如果画面卡顿、延迟明显或推理时间过长，可尝试降低视频分辨率、降低输入帧率、更换轻量模型，或关闭其他占用 GPU 的程序。

### 5.4 参数设置建议

常规检测场景下，可以使用默认置信度和 IOU 阈值。

如果漏检较多，可适当降低置信度阈值；如果误检较多，可适当提高置信度阈值。如果同一目标出现多个重叠检测框，可适当调整 IOU 阈值。

模型选择建议如下：

- 对准确率要求较高时，优先使用改进模型。
- 对实时性要求较高时，可选择较轻量的对照模型。
- 事故类型明确时，使用单任务检测。
- 事故类型不确定时，使用综合事故检测。

## 6. 历史记录与统计分析

### 6.1 历史记录

历史记录页面用于查看系统已保存的检测任务。每条记录通常包括检测时间、使用模型、原始文件名、检测来源、检测类别、置信度和检测结果文件等信息。

用户可以通过历史记录页面查看检测详情，也可以删除不再需要的记录。历史记录可用于事故复核、结果追溯和系统运行检查。

### 6.2 检测结果详情

检测详情用于展示单次检测任务的完整结果，包括原始文件信息、模型信息、检测类别、检测框、置信度和结果图像路径等。

当检测结果用于业务判断时，建议结合原始图像或视频画面进行人工复核，避免仅依赖单次模型输出作出最终判断。

### 6.3 统计仪表板

统计仪表板用于展示系统检测数据的总体情况，包括：

- 总检测次数。
- 今日检测次数。
- 不同检测类别的数量分布。
- 不同模型的使用情况。
- 不同数据来源的检测数量。
- 平均推理耗时。

统计数据可用于评估系统使用频率、模型运行效果和不同事故类别的出现情况。

## 7. 总系统集成说明

实时检测子系统是 lkywSystem 总系统中的一个独立子模块。总系统前端可通过固定地址访问实时检测后端，并根据健康检查接口判断子系统是否在线、模型是否就绪。

本子系统默认后端地址为：

```text
http://127.0.0.1:5000
```

总系统首页的实时检测状态卡通常依赖以下接口判断运行状态：

```text
http://127.0.0.1:5000/api/health
```

当健康检查接口正常返回，并且模型状态为就绪时，总系统可认为实时检测子系统处于可用状态。

在完整联调时，建议按以下顺序启动相关服务：

1. 启动 Integration Hub。
2. 启动传感器或模拟网关。
3. 启动实时检测后端。
4. 启动其他协同响应相关后端。
5. 启动总系统前端。
6. 打开总系统首页并检查实时检测状态卡。

本子系统支持与 Integration Hub 进行事件和命令集成。当检测到火灾、泄露事故等异常目标时，后端可向 Integration Hub 发布检测事件；当上层系统下发检测命令时，子系统可接收并执行对应检测任务。

## 8. 常见问题与维护

### 8.1 服务无法启动

如果后端服务无法启动，应检查：

- Conda 环境是否已激活。
- Python 依赖是否安装完整。
- 5000 端口是否被占用。
- 模型权重路径是否正确。
- 后端启动日志中是否存在模型加载错误。

如果前端服务无法启动，应检查：

- Node.js 和 npm 是否安装。
- 前端依赖是否安装完成。
- 3000 端口是否被占用。
- `npm run dev` 是否正常输出访问地址。

### 8.2 模型未加载

模型未加载通常与权重文件路径有关。应检查 `LKYWDataset_weights` 目录下是否存在对应模型文件，并确认文件名为 `best.pt`。

如果模型文件存在但仍加载失败，应检查：

- 模型文件是否损坏。
- 当前环境中的 ultralytics 和 torch 版本是否兼容。
- 是否缺少自定义模型结构兼容文件。
- CUDA 环境是否可用。

### 8.3 上传或检测失败

上传或检测失败时，应检查：

- 文件格式是否受支持。
- 文件大小是否超过 100MB。
- 文件名是否包含异常字符。
- 后端服务是否在线。
- 浏览器控制台或后端日志中是否有报错信息。

对于视频检测，如果检测时间过长，可先缩短视频片段或降低视频分辨率。

### 8.4 实时流连接失败

实时流连接失败时，应检查：

- 摄像头或视频流地址是否正确。
- RTSP 或 RTMP 服务是否正常运行。
- 网络连接是否稳定。
- 视频流是否能被 OpenCV 正常读取。
- 是否存在端口或防火墙限制。

如果使用 OBS 推流，应确认推流地址、推流密钥和本地流媒体服务配置正确。

### 8.5 结果文件与历史数据维护

系统运行过程中会产生上传文件、检测结果文件和历史数据库记录。长期使用后，应定期清理无用文件，避免占用过多磁盘空间。

建议维护内容包括：

- 定期备份历史数据库。
- 清理无用上传文件。
- 清理过期检测结果图像和视频帧。
- 更新模型权重前备份旧模型。
- 修改配置后重新启动后端服务。

在正式部署或验收前，应确认后端健康检查正常、前端页面可访问、模型能够加载、图片检测和视频检测流程均可正常完成。
