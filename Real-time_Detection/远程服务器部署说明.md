# zby 实时检测子系统远程服务器部署说明

本文用于部署 `Real-time_Detection` 子系统的远程检测后端，并说明：

- 模型文件应该放在哪里
- `venv` 怎么创建和使用
- CPU / GPU 版 PyTorch 怎么安装
- 如何验证推理环境是否可用
- 如何和 `vue-project_all` 总系统对接

适用目录：

- 后端入口：[web_app/backend/app.py](/q:/liangkeweb/lkywSystem/Real-time_Detection/web_app/backend/app.py)
- 后端依赖：[web_app/backend/requirements.txt](/q:/liangkeweb/lkywSystem/Real-time_Detection/web_app/backend/requirements.txt)

## 1. 部署定位

`zby` 这套系统建议拆成两部分理解：

- 远程检测后端：部署在服务器上，负责加载 YOLO 模型、接收 RTSP 流、执行推理、提供 HTTP API。
- 检测前端页面：可以单独打开，也可以由 `vue-project_all` 通过 `iframe` 集成。

当前后端默认监听：

```text
0.0.0.0:5000
```

也就是说，部署成功后，外部一般通过：

```text
http://<服务器IP>:5000
```

访问它。

## 2. 先说结论

远程部署要满足 4 个条件：

1. 服务器上要有 Python 虚拟环境。
2. 服务器上要装好 `torch` / `ultralytics` / `opencv-python` 等依赖。
3. 服务器上必须有可用的 `.pt` 模型文件。
4. 总系统首页和实时检测子系统里要配置正确的后端地址与 RTSP 地址，不能继续用 `localhost`。

这意味着：

- `GET /api/health` 可以在线返回。
- 但如果模型文件缺失，真正开始检测时会失败，状态里会显示 `model_ready: false`。

### 3.3 推荐放置方式

推荐二选一：

## 4. Python 与虚拟环境

### 4.1 推荐 Python 版本

PyTorch 官方当前要求 Python 3.10 或更高版本。

但结合这个项目的依赖情况，建议优先使用：

- Python 3.10
- 或 Python 3.11

原因很简单：这两个版本对 `torch`、`ultralytics`、`opencv-python` 的兼容性通常更稳，排错成本也更低。

### 4.2 创建虚拟环境

以下以 Windows PowerShell 为例。

进入后端目录：

```powershell
cd Q:\liangkeweb\lkywSystem\Real-time_Detection\web_app\backend
```

创建并激活虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

如果 PowerShell 不允许执行脚本，先执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

然后再激活虚拟环境。

升级基础工具：

```powershell
python -m pip install --upgrade pip setuptools wheel
```

## 5. PyTorch 安装说明

这一段最重要。

`[requirements.txt](/q:/liangkeweb/lkywSystem/Real-time_Detection/web_app/backend/requirements.txt)` 里没有显式锁定 `torch`，所以推荐顺序是：

1. 先安装和服务器环境匹配的 PyTorch
2. 再执行 `pip install -r requirements.txt`

官方安装入口：

- PyTorch Get Started: https://pytorch.org/get-started/locally/

### 5.1 只有 CPU，或先做联调验证

如果服务器没有 NVIDIA GPU，或者你只是先验证接口与页面联通，可以直接安装 CPU 版：

```powershell
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

这种方式适合：

- 先把接口跑通
- 先验证 `vue-project_all` 的状态卡与控制按钮
- 小规模图片/视频测试

缺点是实时推理性能通常不够。

### 5.2 使用 NVIDIA GPU

先检查显卡和驱动：

```powershell
nvidia-smi
```

如果命令能正常返回，再安装匹配 CUDA 版本的 PyTorch。当前常见做法是使用官方提供的 `cu121`、`cu124` 或 `cu118` 轮子，具体以 PyTorch 官网选择器为准。

常见示例：

```powershell
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
pip install -r requirements.txt
```

如果你的机器适配 `cu124`：

```powershell
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
```

如果你的环境较旧，也可能需要：

```powershell
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
pip install -r requirements.txt
```

不要盲目照抄。最终以显卡驱动、CUDA 兼容性和官网选择器为准。

### 5.3 验证 GPU 推理环境

安装完成后，执行：

```powershell
@'
import torch
print("cuda_available =", torch.cuda.is_available())
if torch.cuda.is_available():
    print("device_name =", torch.cuda.get_device_name(0))
'@ | python -
```

如果输出里有：

```text
cuda_available = True
```

说明 GPU 推理环境已经基本可用。

## 8. 启动后的验证

### 8.1 健康检查

服务启动后，先检查：

```text
http://<服务器IP>:5000/api/health
```

当前健康检查会返回这些关键信息：

- 服务是否在线
- 模型是否就绪
- 已激活 RTSP 检测流数量

如果你看到：

```text
status: ok
model_ready: true
```

说明后端和模型都已经准备好了。

如果 `model_ready: false`，说明服务起来了，但模型文件没找到，或者路径配置不正确。

### 8.2 RTSP 状态检查

还可以检查：

```text
http://<服务器IP>:5000/api/rtsp/status
```

这个接口会返回：

- 当前是否有活跃检测任务
- 正在检测的流
- 模型是否就绪

## 9. RTSP 视频流怎么接

### 9.1 本地开发调试

本地开发可以继续用类似下面的地址：

```text
rtsp://localhost:8554/live
```

常见来源：

- OBS + RTSP Server 插件
- 本机测试推流器

### 9.2 真实部署

真实部署时，不要继续写 `localhost`。

应该改成远程服务器或边缘现场实际可访问的 RTSP 地址，例如：

```text
rtsp://192.168.2.111:8554/live
```

或者直接使用摄像头 / 编码器提供的 RTSP 地址。

### 9.3 与 lb 子系统的关系

你当前的 `lb` 子系统更偏向边缘端采集与视频接入，它现在代码里主要是：

- 接上游视频流
- 在边缘端做采集与展示

如果后续希望 `zby` 用现场视频做检测，最稳妥的方式是：

- 让 `zby` 直接接真实 RTSP 源
- 或者让边缘端额外明确提供标准 RTSP 地址

不建议长期依赖 `localhost` 调试地址作为正式部署方案。

## 10. 与总系统 vue-project_all 对接

当前总系统首页已经支持配置 `zby` 的后端地址和 RTSP 地址。

部署完成后，在 `vue-project_all` 首页按这个顺序做：

1. 在“实时检测服务”卡片里填写远程后端地址，例如 `http://192.168.2.120:5000`
2. 填写 RTSP 流地址
3. 点击“保存地址”
4. 点击“保存流地址”
5. 点击“开始检测”

这样总系统首页状态卡会持续检查：

- 远程后端是否在线
- 模型是否就绪
- RTSP 检测任务是否已启动

## 11. 防火墙与网络

远程服务器至少要保证这些端口可访问：

- `5000/TCP`：`zby` 检测后端
- `8554/TCP`：如果同机提供 RTSP 服务

如果是 Windows 服务器，至少要确认：

- Python 已放行
- 5000 端口已放行
- 8554 端口已放行

## 12. 常见问题

### 12.1 `/api/health` 在线，但开始检测失败

优先检查：

- 模型文件是否存在
- `YOLO11N_MODEL_PATH` 是否正确
- RTSP 地址是否真实可访问

### 12.2 模型文件明明存在，但还是加载失败

检查：

- 环境变量是不是在当前启动窗口里生效
- 路径是否写成了错误盘符
- 是否使用了相对路径但实际启动目录不一致

建议尽量使用绝对路径。

### 12.3 服务器有 GPU，但还是走 CPU

检查：

- `nvidia-smi` 是否正常
- `torch.cuda.is_available()` 是否为 `True`
- 是否误装了 CPU 版 PyTorch

### 12.4 总系统 iframe 能打开，但首页状态卡显示离线

检查：

- 首页卡片里配置的后端地址是否正确
- 远程服务器是否允许外部访问 `5000`
- 服务器防火墙是否已放行

## 13. 推荐部署方式

当前更合理的落地方式是：

- `lb` 负责边缘采集和现场视频接入
- `zby` 负责远程检测推理
- `vue-project_all` 负责状态总览、页面承载和任务控制

其中视频流建议优先使用边缘端可稳定访问的真实 RTSP 地址，而不是开发期的 `localhost`。
